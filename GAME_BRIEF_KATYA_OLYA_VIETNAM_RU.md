# Игра «Маршрут без фильтра»
## Рабочее ТЗ для Кими и команды разработки

Дата версии: 3 октября 2026 года

> Важное уточнение: в документе везде используются имена **Катя и Оля**. Страна действия — **Вьетнам**, не Таиланд. Непонятное слово из исходной идеи «пусипон» пока не фиксируется как конкретный объект: до уточнения сценаристы используют нейтральную формулировку «сомнительное закрытое мероприятие / приглашение» без эротизации и без графичного контента.

---

## 1. Короткое видение

**«Маршрут без фильтра»** — мобильная 3D-игра о Кате и Оле, двух подругах, которые путешествуют по Вьетнаму. Они знакомятся с добрыми и сложными людьми, ошибаются из-за языковых и культурных недоразумений, сталкиваются с мошенничеством, навязчивыми предложениями, потерей вещей, плохой погодой и сомнительными приглашениями. Игрок не обязан драться: главное оружие — наблюдательность, взаимное доверие, проверка информации, умение сказать «нет», поиск безопасной помощи и способность отвечать за последствия.

### Формат

- 3D narrative adventure / интерактивная дорожная история.
- Исследование небольших локаций, диалоги, лёгкие головоломки, управление временем и бюджетом.
- 6–10 часов на полное прохождение; первый вертикальный срез — 20–30 минут.
- Целевая аудитория: 16+. Никакой графичной жестокости, сексуального насилия, инструкций по употреблению или покупке наркотиков.
- Одна кодовая база для сайта, PWA, Telegram Mini App и, позднее, оболочек Android/iOS.
- Рабочий домен: `game.example.com` или выбранный владельцем проекта домен на Vercel.

### Главная фишка

Игрок управляет не одной героиней, а **связкой Катя + Оля**. У них разные взгляды:

- Катя быстрее действует, любит снимать видео и искать сенсацию.
- Оля внимательнее к деталям, людям и рискам, но иногда слишком долго сомневается.

Важные решения показывают не шкалу «добро/зло», а цену выбора: время, деньги, доверие между подругами, безопасность, репутация и качество полученной информации.

## 2. Результат параллельного исследования

### Рекомендуемый графический стек

**Основной вариант: Babylon.js + TypeScript + React UI.** Babylon.js подходит для браузерной 3D-игры: у него есть WebGL/WebGPU, сцена, камеры, анимация, физика, LOD, инкрементальная загрузка и инструменты инспекции. Официальная спецификация также указывает Native-варианты для мобильных и десктопных платформ: [Babylon.js Specifications](https://www.babylonjs.com/specifications/).

Рендеринг строится так:

1. WebGPU — если устройство стабильно поддерживает его.
2. WebGL 2 — обязательный основной fallback для телефонов и Telegram WebView.
3. Низкий графический профиль — упрощённые тени, LOD, меньшие текстуры, отключение части постэффектов.

**Альтернативы, которые нужно проверить до заморозки стека:**

| Решение | Когда выбирать | Минусы |
|---|---|---|
| Babylon.js | Лучший баланс для web-first 3D, TypeScript, мобильного fallback и готовых систем | Нужно самостоятельно собрать часть игрового фреймворка |
| Three.js + собственные системы или React Three Fiber | Если нужен максимальный контроль и сильная React-команда; WebGPURenderer умеет откатываться к WebGL 2 ([официальная документация](https://threejs.org/docs/pages/WebGPURenderer.html)) | Больше инженерии для физики, инспектора, загрузки и сцены |
| PlayCanvas | Если команда хочет браузерный визуальный редактор и совместное редактирование сцен | Часть командного workflow зависит от коммерческого редактора |
| Godot 4 | Если важнее полноценный редактор, нативные сборки и open source | Web-экспорт требует WebAssembly/WebGL 2; C#-проекты Godot 4 не экспортируются в Web; мобильный web слабее нативного. См. [Godot Web export](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_web.html) |
| Unity | Если приоритетом станут нативные Android/iOS и большая команда Unity | Для Telegram/Web основной билд будет тяжелее; усложняется единая web-first архитектура |
| Unreal Engine | Для высокобюджетного нативного проекта | Не выбирать как основу проекта, где сайт и Telegram Mini App являются обязательными платформами |

### Итог исследования по платформам

- Vercel: разделить статический фронтенд, API и постоянные данные. Vercel на текущей документации поддерживает WebSockets в public beta через Fluid Compute, но соединение привязано к экземпляру функции и требует переподключения; состояние комнат и presence нельзя хранить только в памяти функции. См. [Vercel WebSockets](https://vercel.com/docs/functions/websockets).
- Для первой версии real-time не нужен: игра одиночная. Сохранения синхронизируются обычными HTTPS-запросами.
- Telegram Mini App — не отдельная переписанная игра, а тот же web-build в Telegram WebView. Telegram передаёт `initData`; сервер обязан проверить подпись и свежесть `auth_date`, прежде чем доверять пользователю. См. [официальную документацию Telegram Mini Apps](https://core.telegram.org/bots/webapps).
- Vercel удобно разделить на Local, Preview/Staging и Production; среда, домен и секреты должны быть разными. См. [Vercel Environments](https://vercel.com/docs/deployments/environments).
- Для ветвящихся диалогов использовать Ink/inkjs или собственный JSON-формат. Ink компилирует историю в JSON, а состояние можно сериализовать; это удобно для браузера, сохранений и локализации. См. [репозиторий Ink](https://github.com/inkle/ink).

## 3. Рекомендуемый флагманский сюжет

### Название

**«Маршрут без фильтра: Катя и Оля во Вьетнаме»**

### Завязка

Катя и Оля приезжают во Вьетнам, чтобы снять честный тревел-дневник, а не очередную постановочную рекламу. В первые дни они случайно меняются сумками с другим путешественником. В чужой сумке оказывается карта памяти и несколько фотографий, связанных с сетью фальшивых экскурсий и нелегальных «работ для туристов». Это не повод становиться сыщиками-героинями: сначала подругам нужно понять, что перед ними вообще происходит, не подвергая себя и других опасности.

Одновременно разные люди предлагают им сомнительные поездки, закрытые мероприятия, «лёгкий заработок» и вещества. Катя и Оля отказываются, но поначалу не понимают контекста и не могут отличить обычную вежливость от манипуляции. Игрок постепенно учится проверять адрес, не отдавать паспорт, оставаться в людном месте, связываться с отелем или официальной службой и не публиковать непроверенные обвинения.

### Три акта

**Акт I — «Первый поворот»**

- Аэропорт/отель, рынок, кафе и первая небольшая 3D-локация.
- Игрок знакомится с Катей и Олей через бытовые решения.
- Первая попытка навязать сомнительную услугу или приглашение.
- Катя хочет снять всё сразу; Оля предлагает сначала проверить факты.
- Игрок получает переменные `budget`, `time`, `safety`, `trust_katya_olya`.

**Акт II — «Не всякая подсказка — помощь»**

- Подруги ищут владельца сумки и проверяют карту памяти.
- Появляются несколько правдоподобных версий: ошибка, мошенничество, эксплуатация туристов, обычный конфликт бизнеса.
- Игрок выбирает, кому доверять: сотруднице отеля, местному студенту-переводчику, журналистке, владельцу тура или случайному блогеру.
- Плохая погода, потерянный документ, разряженный телефон или неверный перевод меняют доступные сцены.
- Ошибки не должны мгновенно заканчивать игру: они создают новые последствия и пути восстановления.

**Акт III — «Опубликовать или защитить»**

- У Кати появляется соблазн выпустить сенсационное видео.
- Оля настаивает на проверке фактов и защите людей, которые могут пострадать.
- Финальный выбор: безопасно передать материалы компетентной стороне, опубликовать только подтверждённую часть, отказаться от публикации или рискнуть ради вирусного ролика.
- Финал зависит не только от последнего клика, но и от накопленных решений.

### Варианты финала

1. **«Честный маршрут»** — материалы проверены, местные союзники не раскрыты, подруги сохраняют доверие.
2. **«Сенсация любой ценой»** — ролик становится популярным, но из-за поспешности страдает невиновный человек.
3. **«Мы выбрали безопасность»** — Катя и Оля уходят из истории без доказательств, но помогают одному человеку и возвращаются домой целыми.
4. **«Доверие восстановлено»** — после крупной ссоры подруги признают ошибки и вместе передают материалы журналистке.
5. **«Одна ошибка слишком много»** — потеря документов и денег закрывает часть маршрута, но открывает камерный эмоциональный финал.
6. **«Скрытая ветка»** — при высоких `evidence`, `local_trust` и `cultural_respect` выясняется, что карта памяти была оставлена специально, чтобы найти безопасного свидетеля.

### Три приоритета для прототипа

1. **«Карта без адреса»** — лучший основной MVP: понятная загадка, 3D-исследование и выборы без дорогого боевого контента.
2. **«Фото, которого нет»** — сильнее раскрывает Катю и Олю как авторов тревел-контента.
3. **«Вьетнам без фильтра»** — самый подходящий вариант для образовательной и безопасной подачи, но требует культурного консультанта.

## 5. Игровой цикл

1. Прибыть в небольшую 3D-локацию.
2. Осмотреть объекты и людей.
3. Поговорить с персонажами; часть реплик доступна только при достаточном доверии или внимательности.
4. Выбрать действие: проверить, уйти, позвонить, попросить помощи, снять видео, промолчать, помочь.
5. Получить немедленный результат и отложенное последствие.
6. Перейти на карту маршрута.
7. Потратить время, деньги, заряд телефона и репутацию.
8. Сделать запись в дневнике: что известно, что только кажется правдой.
9. Сохранить прогресс и открыть новый участок истории.

### Переменные истории

```text
safety: 0..100              // насколько безопасно организованы действия
trust_katya_olya: 0..100    // отношения подруг
budget: integer             // деньги
travel_time: integer        // доступное время
battery: 0..100             // заряд телефона/камеры
verified_evidence: 0..10    // только проверенные факты
local_trust: 0..100         // доверие конкретных персонажей, не «оценка народа»
cultural_respect: 0..100    // соблюдение личных и культурных границ
stress: 0..100              // усталость и эмоциональная нагрузка
flags: object               // события и последствия
```

### Принцип ветвления

Не создавать сотни полностью разных уровней. Делать **широкие решения, сходящиеся в общие локации**, но меняющие:

- доступные реплики;
- состояние отношений;
- кто помогает в следующей сцене;
- цену поездки;
- финальное видео и концовку.

Минимум для вертикального среза: 8–12 значимых выборов, 3 варианта финальной сцены, 2 полноценных концовки.

## 6. Визуальный стиль и графика

### Направление

**Стилизованный кинематографичный реализм**, а не тяжёлый фотореализм:

- тёплый дневной свет, ночные неоны, дождь и фонари;
- выразительные лица и одежда, но умеренная детализация;
- реалистичные материалы без перегрузки полигонами;
- интерфейс как дорожный дневник, карта и камера Кати;
- узнаваемые места Вьетнама только после проверки референсов и согласования с консультантом.

### Asset pipeline

```text
Blender / Houdini
    -> clean topology, rig, animation, LOD
    -> glTF/GLB
    -> Meshopt/Draco для геометрии
    -> KTX2/BasisU для текстур
    -> asset manifest + checksum
    -> Babylon.js loader
```

### Цели производительности

Это стартовые бюджеты, которые нужно подтвердить реальными тестами на устройствах:

- 30 FPS на среднем Android — обязательная цель.
- 60 FPS на современных устройствах — целевая цель.
- первые интерактивные действия после загрузки — желательно до 10 секунд на обычном 4G после холодного старта;
- WebGL 2 fallback обязателен;
- на слабом устройстве: динамический resolution scale, LOD, меньшие тени, отключение части частиц;
- не грузить весь Вьетнам одной сценой: отдельные пакеты локаций;
- initial download держать минимальным, остальные GLB/текстуры подгружать по маршруту;
- при сворачивании Telegram или браузера останавливать тяжёлый render loop и сохранять прогресс.

### Локации для MVP

1. Небольшой отель/хостел и улица рядом.
2. Рынок/кафе.
3. Набережная или станция транспорта.
4. Меню карты для перехода между ними.

Не начинать с огромного открытого мира. Качество маленьких сцен важнее размера карты.

## 7. Архитектура проекта

### Monorepo

```text
/apps
  /web                 // основной сайт, PWA и Telegram WebView
  /bot                 // Telegram bot + webhook
  /admin               // редактор контента и QA-панель, закрытая
/packages
  /game-core           // состояние, input, save, story bridge
  /render-babylon      // сцены, камеры, загрузка ассетов
  /story               // Ink/inkjs или JSON runtime
  /content              // диалоги, локализация, параметры сцен
  /ui                   // интерфейс, безопасные кнопки, accessibility
  /platform             // web / Telegram / Capacitor adapters
  /validation           // Zod-схемы и серверная проверка
```

### Фронтенд

- TypeScript.
- React только для меню, диалогов, карты и настроек; 3D-сцена отдельно в Babylon.js.
- Vite или Next.js с клиентским компонентом игры. До выбора фреймворка сделать spike и измерить размер бандла.
- Ink/inkjs для авторского текста или строго типизированный JSON, если команда решит не добавлять Ink.
- IndexedDB для локального сохранения; серверная синхронизация — после авторизации.
- PWA manifest, service worker, безопасное кэширование shell и уже загруженных материалов.

### Backend

- Vercel Functions для коротких API-запросов.
- PostgreSQL через отдельный managed-провайдер, например Supabase/Neon, после проверки тарифов и DPA.
- Redis/Upstash — только если понадобятся rate-limit, кэш или очереди.
- Объектное хранилище/CDN для тяжёлых GLB, KTX2, аудио и патчей.
- Сервер не доверяет клиентским `budget`, `evidence`, achievements и unlocks: проверяет допустимый переход состояния.

### Сохранения

- В гостевом web-режиме: локальный слот в IndexedDB.
- В Telegram: после проверки `initData` создать псевдоним пользователя и хранить облачный слот.
- Синхронизация по версии: `save_version`, `client_updated_at`, `server_updated_at`, checksum.
- Конфликт не перезаписывать молча: показать «выбрать более новый слот / объединить безопасные настройки».

## 8. Стыковка web, телефона, Telegram и Vercel

### Один игровой core — несколько оболочек

```text
Game Core
  ├─ Browser adapter: mouse, keyboard, touch, gamepad
  ├─ Telegram adapter: theme, BackButton, MainButton, initData, haptic if available
  ├─ PWA adapter: install prompt, offline shell, push only with explicit consent
  └─ Capacitor adapter: Android/iOS lifecycle, safe areas, store build
```

### Сайт

- `https://game.example.com/` — лендинг и запуск игры.
- `https://game.example.com/play` — web/PWA.
- `https://game.example.com/telegram` — тот же клиент с Telegram-адаптером.
- `https://staging.game.example.com/` — тестовая среда.
- Домен привязывается к Production в Vercel; Preview deployments используются для каждой ветки.

### Telegram Mini App

1. Создать бота через BotFather.
2. Зарегистрировать Mini App и назначить HTTPS URL.
3. Сделать кнопку меню через `/setmenubutton` и прямую ссылку.
4. Передавать сюжетный стартовый параметр только через разрешённый Telegram-механизм (`startapp`/`start_param`), не доверяя произвольным query-параметрам.
5. На клиенте читать `Telegram.WebApp.initData`, но не считать `initDataUnsafe` доказательством личности.
6. На сервере проверять HMAC-подпись и срок давности `auth_date`.
7. Подстраивать цвета и кнопки под тему Telegram, но не ломать обычный браузерный интерфейс.
8. Проверить iOS Telegram, Android Telegram, Telegram Desktop и Telegram Web.

### Мобильное приложение

**Этап 1:** PWA с установкой на домашний экран — минимальный риск и одна кодовая база.

**Этап 2:** Capacitor wrapper для Android/iOS, если метрики PWA подтвердят спрос. Нативные функции добавлять через adapter, а не в `game-core`.

**Этап 3:** при доказанной потребности в более высоком FPS оценить Babylon Native или отдельный native-клиент. Не переписывать проект на другой движок до измерений.

### Что не делать

- Не делать отдельную игру для Telegram и отдельную игру для сайта.
- Не хранить bot token, database secret или service-role key в клиентском JavaScript.
- Не использовать WebSocket для первой одиночной версии.
- Не требовать регистрации до первого запуска.
- Не загружать гигантскую 3D-сцену до показа первого интерактивного действия.

## 9. Безопасность, приватность и культурная корректность

### Техническая безопасность

1. Все запросы только по HTTPS.
2. Telegram `initData` валидируется на сервере; `initDataUnsafe` используется только для предварительного UI.
3. Проверять `auth_date`, nonce/state и срок жизни сессии.
4. Cookie-сессии: `HttpOnly`, `Secure`, `SameSite=Lax/Strict` по сценарию.
5. CSRF-защита для изменяющих запросов.
6. Content Security Policy, HSTS, `X-Content-Type-Options`, `Referrer-Policy`, безопасный `frame-ancestors` с учётом Telegram WebView.
7. Не вставлять пользовательский текст через `innerHTML`; диалоги — только из доверенного контентного пакета.
8. Схемы API проверять через Zod/аналог; лимиты размера payload.
9. Rate limit на login, save, sync и webhook.
10. Bot webhook защищать секретным URL/заголовком и проверять источник.
11. Dependency pinning, lockfile, Dependabot/Renovate, npm audit, SAST и секрет-сканер в CI.
12. Не принимать достижения, деньги или сюжетные флаги от клиента без серверной проверки.
13. Логи не должны содержать полные Telegram initData, токены, точные координаты или содержимое личных сообщений.
14. Без пользовательского чата и UGC в MVP. Если UGC появится позднее — report/block, фильтрация, модерация и rate limit до релиза.

### Приватность

- Не запрашивать геолокацию, контакты, микрофон и камеру без понятной функции и отдельного согласия.
- Камера в игре — игровая механика, не доступ к реальной камере устройства.
- Хранить минимум: псевдоним, прогресс, язык, настройки, технические события с согласием.
- Сделать страницу Privacy, удаление прогресса и экспорт данных.
- Учесть GDPR для пользователей из ЕЭЗ; отдельно описать возрастной порог.
- Телеметрия по умолчанию минимальная и агрегированная; не записывать содержимое диалогов пользователя.

### Контентная безопасность

- Не показывать инструкции по покупке, дозировкам, изготовлению или сокрытию наркотиков.
- Не романтизировать зависимость, принуждение, эксплуатацию и «опасную вечеринку».
- В сложных сценах варианты игрока: отказаться, уйти в людное место, позвонить доверенному человеку, обратиться к персоналу/официальной помощи, зафиксировать факт безопасно.
- Не обвинять жертву в том, что она «сама виновата».
- Не превращать весь Вьетнам в декорацию опасности: большинство персонажей должны быть обычными людьми с разными интересами, а опасные ситуации — конкретные, а не «национальная черта».
- Не делать из вьетнамского языка шутку. Диалоги, имена, вывески, жесты, еда, история и маршруты проверяет носитель языка или культурный консультант.
- Не использовать реальные организации в качестве злодеев без юридической проверки; для конфликтных структур использовать вымышленные названия.
- Отдельно тестировать тему торговли людьми, сексуального намёка и наркотиков с консультантом по safeguarding.
- Добавить content warning, настройку пропуска тяжёлых сцен и доступный текстовый режим.

### Внутриигровая карточка безопасности

В меню можно добавить необязательный раздел «Полезно в дороге»:

- план маршрута;
- копия документов в безопасном месте;
- контакт отеля или доверенного человека;
- проверка транспорта и условий услуги;
- не отдавать паспорт незнакомым людям;
- обращаться к официальным и проверенным источникам.

Конкретные номера и ссылки не зашивать навсегда в сюжет: их должен проверять владелец проекта перед каждым релизом.

## 10. План производства MVP

План рассчитан примерно на 16–24 недели для команды 5–8 человек плюс AI-инструменты. Для одного человека сроки нужно увеличить.

### Этап 0. Предпродакшн — 1–2 недели

**Результат:** зафиксирован one-page pitch, выбран один сюжет, написан контентный стандарт, подтверждён стек.

- выбрать «Карта без адреса» или «Фото, которого нет»;
- утвердить Катю, Олю, трёх союзников и одного антагониста-ситуацию;
- провести культурный research sprint;
- сделать карту переменных и таблицу концовок;
- проверить Babylon.js vs Three.js на одной сцене;
- создать репозиторий и правила ветвления.

### Этап 1. Технический spike — 2 недели

**Результат:** герой ходит по сцене, работает touch, диалог, сохранение и Preview deployment.

- одна тестовая локация;
- GLB, LOD, KTX2/Meshopt;
- WebGPU/WebGL2 fallback;
- базовая камера и взаимодействие;
- IndexedDB save;
- тест на Android/iOS Telegram WebView.

### Этап 2. Vertical slice — 4–6 недель

**Результат:** 20–30 минут настоящей игры.

- отель, рынок и набережная;
- 8–12 значимых выборов;
- 2 героини, 5 NPC;
- одна сомнительная ситуация, показанная безопасно;
- 2–3 варианта финала;
- русский и английский текст;
- экран предупреждений и доступный текстовый режим;
- автоматические smoke-тесты.

### Этап 3. Alpha — 5–7 недель

**Результат:** начало и середина всей MVP-истории.

- 3–4 локации;
- 90–150 минут контента;
- 6 финалов;
- карта маршрута и журнал;
- облачные сохранения для Telegram;
- контентная панель для сценаристов;
- device matrix: бюджетный Android, средний Android, iPhone, iPad, desktop Chrome/Firefox/Safari, Telegram iOS/Android/Desktop/Web.

### Этап 4. Beta и hardening — 3–5 недель

**Результат:** версия для закрытого тестирования.

- нагрузка API и rate limits;
- security review;
- проверка подписей Telegram;
- восстановление после обрыва сети;
- тесты локализации;
- performance budget;
- исправление культурных и возрастных замечаний;
- подготовка страницы поддержки, Privacy и Terms.

### Этап 5. Запуск — 1–3 недели

- production domain на Vercel;
- Telegram bot и Mini App;
- PWA install flow;
- staged rollout;
- мониторинг ошибок и времени загрузки;
- ручная проверка первых релизных дней;
- план патчей и резервная копия контента.

### Definition of Done для MVP

- Игра запускается по прямой ссылке и из Telegram.
- Сайт и Telegram используют один пакет сюжета и один game core.
- 30 FPS на согласованном среднем Android в вертикальном срезе.
- Сохранение не теряется при обновлении или обрыве сети.
- `initData` не принимается без серверной проверки.
- Нет секретов в публичном JS-бандле.
- Диалоги не допускают XSS и произвольный HTML.
- Есть content warning, skip/comfort options и Privacy.
- Все 6 финалов достижимы и покрыты тестами.
- Ни один тяжёлый сюжетный материал не строится на стереотипе «Вьетнам = опасность».

## 13. Главные решения, которые надо утвердить перед кодом

1. Рабочее название: «Маршрут без фильтра» или другое.
2. Катя и Оля — совершеннолетние? В этом ТЗ предполагается да.
3. Возрастной рейтинг: рекомендуется 16+, без графичного контента.
4. MVP-сюжет: «Карта без адреса» или «Фото, которого нет».
5. Языки релиза: минимум русский + английский; вьетнамские реплики — с проверкой носителем.
6. Нужна ли только PWA/Telegram-версия или сразу публикация в App Store/Google Play.
7. Будет ли у проекта локальный культурный консультант во Вьетнаме.
8. Какой домен будет куплен и кто владеет аккаунтами Vercel, BotFather, Git и БД.
9. Разрешены ли пользователю реальные фото/камера — рекомендуется отложить до отдельного privacy review.
10. Нужен ли второй игрок в будущем — не включать в MVP.
