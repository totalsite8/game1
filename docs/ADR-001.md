# ADR-001: web-first прототип
Дата: 2026-10-03. Статус: временное инженерное решение для прототипа, не утверждение production-дизайна.

## Решение

Берём рекомендованный брифом Babylon.js + React + TypeScript + Vite. Сюжет — типизированные данные с чистой функцией перехода. «Карта без адреса» — первый эпизод. Обе героини взрослые. Возрастное предупреждение 16+. Два языка: RU/EN.

- React управляет меню/диалогами, renderer подключается через lazy import.
- WebGL — работающая база; нет экспериментального WebGPU до device spike.
- 3D-объекты процедурные, не GLB-production assets.
- `src/packages/game-core` — состояние, переходы, валидация импорта повторным проигрыванием истории.
- `src/packages/story` — сценарий, локализация, последствия.
- `src/packages/render-babylon` — сцена/инпут, освобождение ресурсов, пауза при невидимой вкладке.
- `src/packages/platform` — IndexedDB, последовательная очередь записей.
- `api` — health, отдельная проверка Telegram HMAC, отключённое облако.

Это **модульное single-package приложение**, не завершённый monorepo из раздела 7 брифа. Выделить npm workspaces при добавлении bot/admin, чтобы сейчас не поддерживать пустые приложения. Данные `content/characters.ts`, `content/episodes36.ts` — ранние проектные черновики, не игровое покрытие; в UI не загружаются.

## Почему не другие движки

Бриф уже рекомендует Babylon; готовая сцена/камеры/материалы ускоряют web-spike. Three.js потребовал бы больше собственной сборки игрового слоя; Godot/Unity — отдельный тяжёлый export pipeline. Это качественная оценка, **сравнительный benchmark не проведён**. WebGPU, GLB/KTX2/LOD, gamepad и joystick отложены до измерений.

## Приёмка прототипа

- Прямой запуск без аккаунта.
- 12 выборов, все 4 исхода достижимы; сохранения воспроизводимы.
- Все действия доступны через DOM-кнопки без canvas.
- Обновление страницы сохраняет историю; экспорт/импорт/удаление работают.
- Мобильная вёрстка без горизонтального скролла.
- Production build, тесты, отсутствие известных npm audit-уязвимостей на дату проверки.

## Состояние и доверие

Локальный экспорт — **не защищённое серверное достижение**. Replay пересчитывает последствия и отбрасывает присланные счётчики, но пользователь владеет локальными данными. Облачный endpoint отключён, чтобы ни при каких обстоятельствах не выдавать память Vercel-инстанса за постоянное хранилище.

## Offline

Post-build создаёт service worker с hash-version и precache всех файлов сборки (~несколько МБ), в том числе ленивого renderer. API никогда не кэшируется. Новая версия активируется после закрытия старых вкладок; нет принудительного смешивания версий. Полностью офлайн после первой завершённой установки кэша, не до неё. Персональные данные не отправляются на сервер.

## Производительность

Главная не загружает Babylon как JS execution dependency; worker скачивает его для последующего offline. Это компромисс прототипа. К дальнейшему производству: пакеты локаций, отдельный opt-in offline download, WebGPU spike, GPU/device loss handling, FPS benchmark реальных телефонов. Процедурные сцены не соответствуют финальному художественному качеству иллюстрации на обложке.
